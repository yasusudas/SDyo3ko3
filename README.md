# yo3komi

**yomikomi**と読みます（`yo` + `3（mi）` + `ko` + `mi`）。SDカードなどから未取り込みの写真・RAW・動画を撮影日別に保存するmacOSネイティブアプリです。

## 使い方

1. アプリを開き、左側で取り込み元、右側で保存先フォルダを選択します。
2. 自動スキャンと内容の重複照合が完了するまで待ちます。
3. 未取り込みのファイルから必要なものを選び、「取り込む」で開始します。

保存先は `YYYY/MM-DD/元のファイル名`。保存済みメディアは選択できません。日時不明は詳細から日付を指定できます。フォルダ選択時の権限はmacOSに従って付与してください。

## 自動スキャンの条件

起動時・選択中のストレージの接続時・探索設定の変更時に走査します。写真・動画・付随ファイルや日付フォルダに変更の通知があった場合は、まずファイル情報を照合し、実際の変化があるときだけ再スキャンします。Finderの管理ファイルや属性だけの更新、無関係なドライブの接続、接続状態が変わらないMacの復帰では一覧を維持します。

走査中の変更はまとめて完了後に確認し、自動通知で途中の走査をやり直しません。手動の再読み込みは保留中の自動処理を置き換え、停止操作では保留分も解除します。内容ハッシュとコピー前の厳密な検証は維持しています。

## ビルド

macOS 14以降、Xcode/Swift 6対応ツールチェーン。外部パッケージ依存なし。

```sh
./script/build_app.sh        # Releaseビルド、app生成、AdHoc署名
./script/install_app.sh      # ビルドして /Applications へ配置
./script/build_and_run.sh    # ビルドして起動
```

同名のインストール済みアプリは日時付きバックアップへ移してから配置します。ローカル用AdHoc署名で、Developer ID署名・公証は含みません。

索引とジョブ記録は `~/Library/Application Support/yo3komi/`、プレビューキャッシュは `~/Library/Caches/yo3komi/` に保存します。元ファイルは削除・変更しません。保存内容のSHA-256検証を行います。画像のデコード対応はmacOSの対応形式によります。

## 永続的な取り込み履歴

検証が完了したメディアは、ファイル全体のSHA-256とサイズを単位に履歴へ保存します。動画はAVFoundationで映像・音声の圧縮サンプルデータを取り出し、トラックごとのSHA-256と符号化形式を含む内容ハッシュも保存します。コンテナ、作成日時、回転情報、カメラのデータトラック等が変わっても、全映像・音声トラックの内容が一致すれば取り込み済みと判定します。バッファの区切りやトラックの並び順は判定に影響しません。再エンコードされた動画は同一扱いしません。保存先から削除・移動した後も、同一内容は取り込み済みとして除外します。履歴はプレビューや索引のキャッシュと独立し、通常の再読み込みや途中ファイルの整理では消えません。取り込み元や保存先を変更しても同じアプリの履歴を引き継ぎます。

初回は既存の保存先全体の内容を読み、過去の取り込みとして登録します。大量のアーカイブではこの初回処理に時間がかかります。次回からは変化のない保存先ファイルの全ハッシュを再利用します。履歴と照合する取り込み元ファイルは、その走査で内容の全ハッシュを計算します。導入前に既に削除され、履歴も残っていないファイルは自動復元・判別できません。

履歴はApplication Support内の `history.sqlite3` と `HistoryRecords/` に保持します。中断した履歴結合は `HistoryMerges/` の記録から復旧します。アプリの移行・バックアップ時はこのフォルダ全体を保持してください。

以前の履歴は自動移行して保持します。現存する保存先動画には次の走査で内容ハッシュを追加します。保存先に存在しない旧動画でも、SD側が従来のファイルハッシュと一致すれば内容ハッシュを補えます。元・先の両方が既に変更され、古い内容ハッシュも残っていない場合、その過去の同一性は復元できません。動画の内容を読み取れない場合は新規として自動選択せず、確認が必要な状態にします。

## 履歴の書き出し・読み込み

設定の「履歴」またはメイン画面の「その他」からJSONファイルを書き出し・読み込みできます。読み込みは既存の履歴との和集合を取り、同じファイル全体のSHA-256・サイズの記録を1件に結合します。追加の保存場所、過去の取り込み日時、動画の内容ハッシュも保持します。別コンテナの同じ動画は内容ハッシュで関連づけ、元ファイルのハッシュも残します。同じ履歴を繰り返し読み込んでも件数は増えません。写真・動画の実体は読み込み・復元しません。

JSONは `format: "yo3komi-history"`、`version: 1` の形式です。日時はUTCのUnix秒（小数あり）。ファイル名・取り込み元/保存先パスを含むため、共有先に応じて保管してください。全件を検査してから結合を開始し、不正な形式や同じファイルの競合する動画ハッシュがあれば既存履歴を保持して停止します。結合後は一覧を再照合します。書き出し・読み込みは走査や写真取り込みの実行中には行えません。

## アプリアイコンの再生成

`Resources/AppIcon.png` は1024×1024、8-bit RGBA、全面不透明のマスターです。背景を端まで塗り、角丸や透明な余白を焼き込みません。PNGを変更したら `./script/generate_app_icon.sh` で各解像度のICNSを生成します（再生成時のみImageMagickが必要）。通常のアプリビルドは同梱のICNSを使います。
